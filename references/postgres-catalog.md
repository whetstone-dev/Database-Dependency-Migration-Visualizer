# Catalog capture

`src/dbdep/catalog.mjs` contains the exact allowlisted SELECTs. They inspect pg_namespace, pg_class, pg_attribute, pg_type, pg_constraint, pg_index, pg_depend, pg_rewrite, pg_proc, pg_trigger, pg_inherits, pg_extension and pg_attrdef. Relation references use pg_catalog explicitly; the only explicit function call in current discovery is built-in current_setting. Default expressions use the stored `adbin::text` node tree, then become hashes. Discovery avoids pg_get_expr because deparsing constants can invoke custom data-type output functions. Routine bodies, privileges, database names, connection URLs and user rows are not extracted.

Use a dedicated login with CONNECT and catalog visibility. No table SELECT grants are required for the shipped fixtures. Startup options restrict search_path, apply 10-second statement and 2-second lock timeouts, and default to read-only transactions. The pg client uses fixed BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY and COMMIT statements so discovery queries share one snapshot. Discovery payload queries are SELECT only. DSN options cannot override the startup safeguards. A read-only transaction alone does not establish safety; fixed relation/function allowlists do.

Captures contain actual query hashes, timestamp and selected rows. Default expressions become SHA-256 hashes before persistence. The catalog adapter checks the query-set/hash contract, maps class/OID/subidentifier addresses and collapses rewrite rule/default ownership to views/columns while preserving address provenance. Structural FK/index/trigger/inheritance edges use their actual catalogs. Internal/automatic/normal/extension/partition dependency codes remain edge properties. Built-in system objects are omitted; non-modeled unresolved endpoints are recorded. pg_class statistics are labeled estimates. No actual table size/traffic or runtime coverage is asserted.

The normalized capture format is project-specific, not an arbitrary pg_dump/CSV export. New live captures use `capture_version: "1.1.0"`; the canonical model remains 1.0.0. Offline `inspect --catalog` also accepts 1.0.0 captures against their exact legacy fixed-query hashes, including the former deparsed default-expression representation. It never executes a query from an imported capture. Authentic legacy captures and their evidence remain unchanged. Catalog/repository merge is unavailable; use separate offline query inspection.

The checked-in analytics fixture was captured from a real isolated PostgreSQL server. See `examples/analytics/capture-provenance.json` for version, SQL hashes, capture hash and original execution commands. Run `pnpm test:live` to verify catalog capture in a fresh isolated cluster. `node scripts/fixture-cluster.mjs --update-fixtures` explicitly recaptures the fixture and provenance. Never run fixture setup against a production connection.

Default-expression hashes from 1.0.0 and 1.1.0 captures use different representations. A diff across capture versions can therefore report a changed default without a semantic change. Compare captures of the same version or review this representation change explicitly; do not reinterpret historical hashes as current stored-tree fingerprints.

Authoritative semantics: [pg_depend](https://www.postgresql.org/docs/18/catalog-pg-depend.html), [pg_rewrite](https://www.postgresql.org/docs/18/catalog-pg-rewrite.html), [pg_constraint](https://www.postgresql.org/docs/18/catalog-pg-constraint.html). These cover recorded database dependencies; function strings and application SQL can escape them.
